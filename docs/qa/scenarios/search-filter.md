# 시나리오: 검색 + 필터 (Search & Filter)

> 담당 iOS: `ios-store`. 담당 QA: `qa-functional`. 다국어: `qa-localization`.

## 사용자 플로우

지도 또는 탭바에서 검색 진입 → 키 입력(250ms 디바운스) → 결과 → 필터 시트 → 적용 → 결과 갱신.

## Given (전제)

- 사용자 로그인 + 위치 권한 부여.
- mock 매장 fixture ≥ 30 (서울/도쿄/뉴욕/런던/베를린/파리 분포).
- 사용자에게 최근 검색어 ≥ 2 존재 (`UserDefaults`).

## When (액션)

1. 검색 진입 (지도 상단 검색바 탭 또는 탭바).
2. 빈 상태 — "최근 검색" + "추천 매장" 표시.
3. "말차" 입력 (한 글자씩 1초 간격).
4. 250ms 디바운스 후 자동 검색 → 결과 도시별 그룹.
5. "필터" 버튼 탭 → 하프 시트 표시.
6. 필터: "별점 ≥ 4", "오픈 중", "와이파이" 토글.
7. "적용" 탭 → 결과 갱신 (카운트 변동).
8. 결과 카드 1개 탭 → StoreDetailScreen.

## Then (검증)

- [ ] 250ms 디바운스 동작 — 키 입력 중에는 fetch 중지.
- [ ] 결과는 도시별 섹션 헤더 + 매장 카드 (이름/평균/거리/태그).
- [ ] 필터 적용 시 결과 카운트 즉시 갱신 + 칩 형태로 적용 필터 표시.
- [ ] 빈 query 복귀 시 최근 검색/추천 다시 표시.
- [ ] 결과 0개일 때 빈 상태 카피 + "필터 초기화" CTA.
- [ ] 검색어 → `recentSearches` 큐에 prepend (LRU 10).

## Edge cases

| ID | 상황 | 기대 동작 |
|---|---|---|
| E1 | 빈 query | 최근 검색 + 추천 매장 표시 (검색 호출 0) |
| E2 | 결과 0개 | 빈 상태 카피 + "필터 초기화" + "매장 제안하기" CTA |
| E3 | 1글자 query (a, ㅁ) | 250ms 디바운스 후 fetch — 짧아도 호출 (서버에서 결정) |
| E4 | 100자 초과 query | 100자 캡 + inline 안내 |
| E5 | 특수문자/이모지 | URL 인코딩 정상, 결과는 부분 매치 |
| E6 | 한자/한국어/일본어 mix | locale-agnostic 검색, 모든 글자 매치 |
| E7 | 필터 모두 OFF | 기본 검색 결과 (필터 칩 0) |
| E8 | 네트워크 끊김 | 캐시된 최근 결과 + 토스트 |
| E9 | 빠른 연속 입력 (100ms 간격) | 디바운스로 마지막만 fetch — race 없음 |
| E10 | 시트 dismiss 후 재진입 | 상태 보존 (입력어 + 필터 + 스크롤 위치) |

## 예상 회귀 위험도

**P1** — 발견 경로의 보조. FAIL 시 머지 가능하나 다음 스프린트 fix.

## 다국어 영향

- 6개 언어 placeholder ("매장 검색", "Search stores", "Geschäfte suchen", "店を検索", "Rechercher des cafés", ...).
- 도시 섹션 헤더는 시스템 locale 기반 도시명 (예: "도쿄" / "Tokyo" / "東京").
- 필터 칩 라벨 6개 언어 + 독일어 길이 검증.

## 접근성

- VoiceOver: 검색바는 "매장 검색, 텍스트 입력 필드".
- VoiceOver: 결과 카드는 "{매장명}, 별점 {n.n}, 거리 {n}m, 두 번 탭하여 자세히".
- Dynamic Type: 결과 카드 높이 확장, 도시 헤더 sticky 유지.
- 필터 시트: 토글마다 음성 라벨 + 상태(켜짐/꺼짐).
